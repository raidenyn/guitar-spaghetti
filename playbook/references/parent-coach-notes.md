# Parent and Coach Notes

Your job is to make the child's discoveries possible, not to finish the game
quickly. The child normally operates the mouse and keyboard. This puts
**FC-08** into practice: the child stays in control of the editor while the
adult is a calm second pair of eyes.

## The adult's useful jobs

- **Wait.** After asking a question, count quietly to about ten before giving a
  hint. New programmers often need that time to look and think.
- **Give a smaller hint before an answer.** Try “Which panel shows the first red
  message?” before pointing at the exact line. If that does not help, narrow it
  once more.
- **Read errors together.** Invite the child to read the first red error aloud,
  identify a file and line number, and compare it with the current step.
- **Pause before frustration grows.** A short stretch, drink, or saved stopping
  point is a successful learning decision, not a failure.
- **Praise observations, not speed.** “You noticed the node name has a different
  capital letter” is more useful than “You are fast at this.”
- **Keep experiments reversible.** Save first, change one thing, observe it,
  then undo or restore the lesson checkpoint. Record an optional experiment in
  the progress state before returning to the required path.

## A 30–45 minute session rhythm

1. **Reconnect — 3–5 minutes.** Read the saved checkpoint and let the child
   describe what the game did last time.
2. **Build and check — 20–28 minutes.** Work in small action groups. Stop for
   the exact observation requested by each evidence gate.
3. **Tiny experiment — 3–5 minutes.** If the required checkpoint has passed,
   change one harmless value such as a colour or position, predict the result,
   then restore it.
4. **Explain and save — 4–7 minutes.** Ask one brief explain-it-back question,
   save the scene, and record the next action in the handoff.

## Questions that invite thinking

- “What do you predict will move if we change this y value?”
- “What changed in the Scene tree after we added that node?”
- “Can you point to the first word in the error that looks important?”
- “What evidence would show that the score went up by exactly one?”

These are **FC-09** questions: short invitations to think, not a surprise
lecture or test.

## When you want to take over

Say what you see without touching the controls: “I see a yellow warning icon.
Would you like to click it and read it together?” If typing is tiring, the
adult may slowly dictate a short lesson-prescribed line while the child types.
Avoid silently correcting code, clicking ahead, or deciding that a vague “it
works” is enough evidence. The learning includes noticing, recovering, and
explaining.

## A kind recovery script

“We found a clue, not a bad result. Let’s keep the current step small: read the
first red line, make one correction, and run the same check again.”

This follows the playbook's `DIAGNOSE` path: observe, make one local change,
and repeat the original evidence gate.
